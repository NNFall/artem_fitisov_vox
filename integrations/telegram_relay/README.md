# Доставка Отчётов «ВСЕ | МЕБЕЛЬ» В Telegram

Изолированный сервис для доставки из Voximplant через сервер, когда прямое
соединение Voximplant с Telegram завершается сетевой ошибкой. Он не запускает
Telegram-polling, обзвон или фоновые задачи основного backend.

## Настройки

Переменные окружения сервиса:

- `TELEGRAM_BOT_TOKEN` — токен выбранного Telegram-бота.
- `TELEGRAM_CHAT_IDS` — разрешённые получатели, через запятую.
- `RELAY_AUTH_TOKEN` — отдельный случайный секрет авторизации Voximplant.
- `RELAY_DB_PATH` — SQLite-квитанции; по умолчанию `/data/relay.sqlite`.

Реальные значения хранятся только в `.env` сервера с правами `0600`.
Исходники, Git и логи их содержать не должны. Docker-контекст исключает
`.env`, данные и кеш Python.

Контейнер запускается отдельным compose-проектом:

```sh
docker compose -p vsemebel-relay -f docker-compose.vsemebel-relay.yml up -d --build
```

Порт контейнера опубликован только на `127.0.0.1:8013`. Внешний доступ —
через существующий HTTPS nginx. Рабочий путь:
`https://obzvonai.ru/integrations/vsemebel-telegram/send-message`.
`GET /health` проверяет доступность сервиса, но не доказывает доставку в Telegram.

## Контракт

`POST /send-message`, заголовок `Authorization: Bearer <RELAY_AUTH_TOKEN>`.
Тело JSON: `chat_id`, `text`, необязательный `message_key`.
Сервис принимает только разрешённых получателей, до 32 KiB JSON и до 3900
символов текста. Токен бота и адрес Telegram нельзя передать в запросе.
`parse_mode=HTML` фиксирован на сервере. Успех возвращается только после
ответа Telegram `ok=true` с реальным `message_id`.

Уникальный `message_key` сохраняется в SQLite вместе с хешем сообщения
и квитанцией. Повтор того же успешного запроса возвращает прежний ID без
новой отправки. Другой текст под тем же ключом отклоняется. При неопределённом
результате, например тайм-ауте после отправки, автоматического повтора нет:
он мог бы создать дубликат. Это не долговременная очередь доставки с ретраями.

## Voximplant

Отдельные Secrets сценария:

- `VSEMEBEL_TELEGRAM_RELAY_URL` — HTTPS endpoint выше.
- `VSEMEBEL_TELEGRAM_RELAY_SECRET` — тот же секрет авторизации.
- `VSEMEBEL_TELEGRAM_CHAT_ID_ADMIN` — получатели отчётов.
- При необходимости `VSEMEBEL_TELEGRAM_CHAT_ID_USER`.

Для совместимости сценарий поддерживает прямой Telegram и общие настройки
`TELEGRAM_*`, но рабочий контур использует relay. Отдельный префикс позволяет
не менять Telegram-бота исходящего обзвона. Токен целевого бота хранится на
сервере relay, а не передаётся Voximplant в каждом запросе.

Рабочий получатель — прежний бот JustWood «Тестовый»,
[@demoliveapi_bot](https://t.me/demoliveapi_bot).
Исторический токен этого бота ранее находился в старом исходнике и Git-истории;
его необходимо перевыпустить через BotFather, обновить серверный `.env`
и пересоздать только контейнер relay. Публиковать заново голосовой сценарий
при замене токена бота не требуется.
